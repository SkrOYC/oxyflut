### B002-WIN-10 two-stream, two-display procedure

Use a physical Windows host with two or more occupied outputs at different refresh rates. Create one noncandidate `HWND` per occupied output and create its flip-model swap chain with `IDXGIFactory2::CreateSwapChainForHwnd`. Freeze `DXGI_SWAP_CHAIN_DESC1` to `BufferCount=2`, `Format=DXGI_FORMAT_B8G8R8A8_UNORM`, `SampleDesc.Count=1`, `SampleDesc.Quality=0`, `BufferUsage=DXGI_USAGE_RENDER_TARGET_OUTPUT`, `SwapEffect=DXGI_SWAP_EFFECT_FLIP_DISCARD`, and `Flags=DXGI_SWAP_CHAIN_FLAG_FRAME_LATENCY_WAITABLE_OBJECT`. Do not include `DXGI_SWAP_CHAIN_FLAG_ALLOW_TEARING`. `DXGI_SWAP_CHAIN_DESC1` owns the swap-chain fields, and `DXGI_SWAP_EFFECT_FLIP_DISCARD` is a flip-model value. [S50] [S51] [S61]

After obtaining `IDXGISwapChain2`, call `SetMaximumFrameLatency(1)` and record its `HRESULT`. Abort the output epoch unless it returns `S_OK`. Get the frame-latency handle with `GetFrameLatencyWaitableObject`, and record that handle as the scheduler identity. Microsoft requires the waitable-object creation flag for that method, and makes `SetMaximumFrameLatency` valid only on a waitable-object swap chain. Obtain the QPC frequency once with `QueryPerformanceFrequency`; record every QPC observation with that frequency. [S27] [S40] [S49] [S64]

Set `continuousInvalidation=true` before each measured phase and keep it true for the complete phase. The scheduler must not wait for `WM_PAINT` or an application invalidation. Its complete per-frame loop is: wait on the frame-latency handle with `WaitForSingleObject(handle, 100)`; record the wait result; on `WAIT_OBJECT_0`, record the opportunity QPC timestamp before rendering; clear the acquired render target to a solid deterministic RGBA color derived from monotonically increasing `frameId`; call `IDXGISwapChain::Present(1, 0)`; and record `frameId`, the clear color, the QPC submission timestamp, and the returned `HRESULT`. The clear gives every submitted frame deterministic content, while `frameId` identifies it in the trace. A timeout records no opportunity and lets shutdown check the stop flag. `Present` with sync interval 1 synchronizes to one vertical blank in the flip model. [S20] [S41] [S62]

The harness meter is a separate worker that repeatedly calls `IDXGIOutput::WaitForVBlank` against the output in the scheduler's active epoch. After each successful return, it records its QPC timestamp. The meter never writes scheduler state, decides an invalidation, or calls `Present`. `WaitForVBlank` blocks until vertical blank; the scheduler's waitable-object signal is a separate stream. [S16] [S27]

Determine the active mode before every phase and after every topology or window-output change. First call `GetContainingOutput`, then read `DXGI_OUTPUT_DESC.Monitor` to obtain the scheduler's `HMONITOR`. Pass that monitor to `GetMonitorInfoW` with `MONITORINFOEXW` and record `szDevice`. Size the arrays with `GetDisplayConfigBufferSizes`, then call `QueryDisplayConfig(QDC_ONLY_ACTIVE_PATHS | QDC_VIRTUAL_MODE_AWARE | QDC_VIRTUAL_REFRESH_RATE_AWARE)`. For every active path, request `DISPLAYCONFIG_SOURCE_DEVICE_NAME` through `DisplayConfigGetDeviceInfo`, using that path's source adapter LUID and source ID. Match `viewGdiDeviceName` exactly, case-insensitively, to `MONITORINFOEXW.szDevice`. Reject an epoch if zero or multiple active paths match. [S17] [S18] [S53] [S58] [S59] [S60] [S65]

For the one matched path, record the source adapter LUID and ID, target adapter LUID and ID, `targetInfo.refreshRate` as `virtualRefreshRate`, and every indexed `DISPLAYCONFIG_MODE_INFO`. If `DISPLAYCONFIG_PATH_SUPPORT_VIRTUAL_MODE` is set, select `targetModeInfoIdx`; otherwise select `modeInfoIdx`. The selected mode entry must have `infoType=DISPLAYCONFIG_MODE_INFO_TYPE_TARGET` and matching target adapter LUID and ID. When that entry is available, record `targetMode.targetVideoSignalInfo.vSyncFreq` as `physicalRefreshRate` and use it as the active period `T`; otherwise record `physicalRefreshRate=null` and use `virtualRefreshRate` as `T`. Reject the epoch if any rational used for `T` has a zero numerator or denominator. When `DISPLAYCONFIG_PATH_BOOST_REFRESH_RATE` is clear and both rationals are available, reject the epoch if their refresh frequencies differ by more than 0.1%. When the flag is set, do not apply that consistency check: Microsoft documents `virtualRefreshRate` as virtual and `physicalRefreshRate` as physical in that state. A boosted path without a target entry or a valid physical rational retains B002-WIN-10-VRR as a KU because the required pair cannot be preserved; it is not a consistency-check rejection. Otherwise preserve both values and run B002-WIN-10-VRR. The path structure owns `targetInfo`; the target structure identifies the refresh rational and target mode; the mode table identifies a target entry; and the video-signal structure defines `vSyncFreq`. This replaces `IDXGIOutput::GetDisplayModeList`, which enumerates supported modes and does not identify the active mode. [S53] [S54] [S55] [S56] [S57]

The PRD defines a display epoch as "A measured interval during which a view has one display association and display timing source." Define the output-epoch equality tuple as the output identity (`HMONITOR`, `szDevice`, source adapter LUID and ID, and target adapter LUID and ID), the active-mode timing values (`virtualRefreshRate` and `physicalRefreshRate` when available), and `DISPLAYCONFIG_PATH_BOOST_REFRESH_RATE` state. The QPC timestamp of the display-configuration query is epoch metadata and a display-query record identifier, not a tuple member. End the epoch before processing a record whose equality tuple differs, and start a new epoch only after the mapping succeeds again. A `phaseId` separately records the intentional scheduler-only, co-run, meter-only, and migration phase boundaries; a phase boundary does not create an output epoch. During a window move, both workers must stop the affected phase, resolve the new tuple, and resume. A new output epoch results only when that tuple changes. Unmoved outputs must retain their epoch and scheduler cadence. [S17] [S18] [S53] [S54] [S58] [S59] [S60]

Freeze the variable-refresh policy to the no-tearing path: the swap-chain flags contain only `DXGI_SWAP_CHAIN_FLAG_FRAME_LATENCY_WAITABLE_OBJECT`, and every frame uses `Present(1, 0)`. `DXGI_PRESENT_ALLOW_TEARING` requires sync interval 0, so this loop cannot use that flag. Record `DISPLAYCONFIG_PATH_BOOST_REFRESH_RATE`, `virtualRefreshRate`, and `physicalRefreshRate` from the active path and retain B002-WIN-10-VRR as a separate gate for graphics-driver and panel state. If the boost flag is set, retain its trace, execute the B002-WIN-10-VRR characterization, and exclude its epoch only from the fixed-rate B002-WIN-10 calculation. Do not reject it merely because the virtual and physical rationals differ. [S20] [S52] [S53] [S54]

For every scheduler and meter record, preserve `role`, QPC timestamp and frequency, `HWND`, swap-chain identity, `HMONITOR`, output epoch, worker identity, wait result or `HRESULT`, `frameId` when applicable, and the interval from the same role's preceding record. For every output, capture a 10-second settled scheduler-only baseline, then a 10-second settled two-stream co-run. An optional 10-second meter-only phase can characterize the meter, but cannot control the scheduler noninterference comparison.

For this fixed-rate calculation, an eligible scheduler observation is a record in a settled scheduler-only or co-run phase with a successful output-epoch mapping, a non-boosted epoch, one finite QPC timestamp with a positive QPC frequency, `WAIT_OBJECT_0`, and a following `Present(1, 0)` result of `S_OK` for the same `frameId`. An eligible meter observation is a record in the same non-boosted phase and output epoch with one finite QPC timestamp, a positive QPC frequency, and a successful `WaitForVBlank` result. Reject records without the required `role`, `phaseId`, output epoch, `HWND`, swap-chain identity, or result fields; do not silently repair or infer them. Set `N=100`: each required stream must contain at least 100 eligible observations in its 10-second settled phase, which requires 10 observations per second and prevents a degenerate trace from passing correlation from one or a few events. The optional meter-only phase cannot satisfy an acceptance count. Fail the output if an attempted scheduler `Present`, scheduler wait, or required meter call in a measured phase fails, even when other records meet eligibility.

For each required stream in each output and phase, calculate count, minimum, p50, p95, p99, maximum, and its same-role consecutive interval distribution.
